# 大白饭余额（dsh-baifan-balance）

在 DSH 里**看得见**大白饭中转站（白饭API，new-api 二开）的剩余额度，不用开口问、也不用打开网站。

三处入口，一个数据源：

| 位置 | 形态 |
| --- | --- |
| **输入框下方统计行** | 并进「轮次 / 速度 / token / 缓存命中」那一行，末尾多一个硬币条目：`¥136.80`，点一下立刻重查 |
| **侧栏底部、头像旁** | 紧凑按钮：`🪙 ¥136.80`，侧栏收起成图标列时只留硬币轮廓；悬停看完整明细 |
| 对话里 | `relay_balance` 工具 或 `/balance` 斜杠命令 |

底部条和胶囊每分钟自动刷新，**点一下立刻重查**（绕过 Host 侧 30 秒缓存）。

## 两种凭据都支持

| 凭据 | 走哪个接口 | 能拿到什么 |
| --- | --- | --- |
| `sk-` 推理密钥 | `/v1/dashboard/billing/subscription` + `/usage` | 剩余、已用、总额 |
| 访问令牌（系统令牌） | `/api/user/self` | 同上，外加账号、分组、请求数 |

不用你选：插件按形态自动选通道，一条失败会换另一条。地址传成带 `/v1` 的也会自动去掉。

换算用的 `quota_per_unit` / `quota_display_type` / `usd_exchange_rate` 每次从站点公开的
`/api/status` 读取（缓存 5 分钟），与 new-api 后端 `controller/billing.go` 一致。
**读不到就报错，不会用默认值凑一个好看的数字。**

浏览器侧只读 `GET /baifan-balance/summary`（本机回环），返回内容里没有完整凭据，只有来源和末四位。

## 设置

**点头像 → 设置 → 中转站余额**，一页搞定三件事：

| 字段 | 说明 |
| --- | --- |
| 站点地址 | 不带 `/v1`；换别的 new-api 站点也能用 |
| 密钥 / 访问令牌 | 留空＝不改动；存进 DSH 的**凭据存储**，不写进插件配置 |
| 超时（毫秒） | 整次查询的总预算，3000–120000 |

页面上还有**保存**、**测试查询**（立刻查一次并显示结果）和**清除已保存的密钥**，
并会写明当前生效的凭据来自哪里、末四位是什么——配错时能当场看出来。

写回用的是 DSH 官方的 `configEditor`（站点地址/超时进你的 profile patch）与
`credentials.modifyRecord`（密钥进凭据存储）；保存站点地址后插件会重启一次，属正常。

## 凭据从哪来

按优先级依次尝试，先命中的生效，结果里会写明用的是哪一份（`凭据：…来自插件配置`）：

1. 调用参数 `key`
2. 插件配置 `key`
3. **设置页保存的密钥**（凭据存储）
4. 本包目录下的 `secret.json`，形如 `{"token":"..."}`
5. 环境变量 `BAIFAN_BALANCE_TOKEN` 或 `NEWAPI_ACCESS_TOKEN`
6. 环境变量 `DABAIFAN_API_KEY`——已经把中转站配成 DSH 模型提供商的用户不用再配一遍

改配置时在 profile 自己的 `cordis.patch.yml` 里按 id 覆盖，保存后即时生效：

```yaml
- id: baifan-balance
  config:
    baseUrl: "https://baifanapi.awstme.top"
    key: "sk-..."
    timeoutMs: 15000
```

> `secret.json` 只是让本机开箱即用，**分发给别人前要删掉**，否则会把你的凭据一起发出去。

## 边界

- **只读**：只发 GET，不改状态、不消耗额度。
- **不落盘**：界面上一秒钟的余额、对话里的结果，都不写文件。
- **超时**：`timeoutMs` 是整次查询的总预算（默认 15 秒，含失败后换通道重试）。
- **安全**：调用时传 `base_url` 必须同时传 `key`，避免配置里的凭据被送到别处；也尽量不要把密钥当参数贴进对话。
- **不做静默兜底**：接口字段变形、站点不是 new-api、令牌失效、连不上，都会给出具体原因，不会显示成「剩余 ¥0.00」。
- **语言**：界面与结果文本是中文（站点用户是中文）；`locale/en.json` 只覆盖 Plugin Manager 里的标题与描述。
